What it keeps off the wire

176× less text reached cloud context on a single recorded commit.

From one real line of this repo's own usage ledger: the local model read a 9,184-character staged diff and returned a 52-character commit message. That is one call, not an average — the ledger records counts only, and you can read yours with ollama_ask.py stats.

  • 9,184 characters of diff read locally, on your machine
  • 52 characters Claude actually read back
  • 0 lines of diff body in cloud context — Claude sees --stat only

Why it is built this way

  • Private by default

    Staged diffs, log bodies and file contents go to localhost:11434. The skills forbid Claude from reading what was delegated — no git diff --cached, no git log -p. A digest's judge is capped at three targeted probes.

  • Nothing to install

    One Python file, standard library only, 3.9+. No pip packages, no build step, no API key, no telemetry. The usage ledger stores counts — never prompt content, paths, or repo names, and a unit test enforces that.

  • Never trusted blind

    Every draft is an untrusted draft until its trust tier's gate passes. Drafted commands hit a deny-list and still go through Claude Code's normal permission prompt. Nothing here bypasses permissions.

  • Fails safe, always

    An explicit exit-code contract covers every failure: Ollama unreachable, model missing, stalled, or output rejected. On any of them Claude does the task itself and says so. A failed delegation never blocks your work.

What you can hand off

Ask in plain words

Skills route automatically once you paste the plugin's snippet into your CLAUDE.md — or invoke one directly with /ollama-skills:ollama-commit.

You sayWhat runs
“check the local model setup” ollama-ask — version, installed models, free RAM, size warnings
“commit my staged changes, use the local model” ollama-commit — the diff never enters Claude's context
“pre-commit is failing, fix it” ollama-precommit — deterministic fixers first, then a drafted patch
“zip the logs folder” ollama-shell — drafted command, deny-list check, permission prompt
“write a small parser for X” ollama-code — draft, then line-by-line review behind a test
“summarize errors in app.log” ollama-digest — log, text or git range; Claude never reads the raw input wholesale
“why does this container keep crashing?” ollama-docker — container logs digested locally, then checked
“open a PR for this branch” ollama-pr — drafted description, opened as a draft PR via gh or glab

Honest limits

Claude Code itself still needs the internet. These skills make subtasks local, not Claude.

Small local models are weak. That is why every skill forces Claude to review their output as an untrusted draft before anything is used.

It does not reliably save cloud tokens in unattended sessions. Five rounds of A/B measurement — published in full, negative results included — show deltas smaller than the run-to-run noise, so we make no token-saving claim for neutral-prompt headless runs. The privacy property is the honest headline; savings show up in interactive sessions with several delegations. Read the measurements →

CPU-only machines are slow with big models. The defaults here are tuned for that, from measured numbers. Per-hardware advice →

Five minutes, fresh machine

Quick start

Needs Ollama running locally, Python 3.9+, git, and Claude Code 2.x. The PR skill additionally wants gh or glab, authenticated.

  1. Install Ollama and start it — ollama serve, or the desktop app.
  2. Pull two small models: ollama pull gemma2:2b and ollama pull qwen2.5-coder:1.5b. Any Ollama model works; these are the tested defaults.
  3. Install the plugin with the two commands at the top of this page.
  4. Paste the routing snippet into your project's CLAUDE.md — delegation only happens reliably when CLAUDE.md says when to delegate.
  5. Say “check the local model setup” in Claude Code. You should see your Ollama version, installed models with sizes, and free RAM — with a warning beside any model too big for your machine.
